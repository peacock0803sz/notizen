# notizen

Personal notes and diary manager for the command line.

## Prerequisites

- Go 1.25+ to build from source
- git is required for `commit`, and for automatic repo-name detection in `specs` and `superpowers` (skippable with `--name`)
- rsync for `sync`

## Installation

### Pre-built binaries

Grab a tarball from [GitHub Releases](https://github.com/peacock0803sz/notizen/releases) (linux and darwin, amd64 and arm64), extract it, and drop the binary into your `$PATH`:

```sh
tar xzf notizen-darwin-arm64.tar.gz
mv notizen-darwin-arm64 /usr/local/bin/notizen
```

### Build from source

```sh
go install github.com/peacock0803sz/notizen/cmd/notizen@latest
```

## Quick Start

```sh
notizen diary      # create today's diary entry
notizen commit     # stage, commit, and push changes
notizen sync       # rsync source/ to a remote server
```

## Commands

### `notizen diary`

Creates today's diary entry at `<root>/source/Diaries/YYYY/MM/DD.md`, along with year and month directories and their index files.

| Flag | Description |
|------|-------------|
| `--no-mkdir` | Do not create missing directories |

### Global Flags

| Flag | Description |
|------|-------------|
| `--root` | Root directory for notizen data (default: `~/.notizen`) |

### `notizen commit`

Fetches from origin, pulls, stages everything under `source/`, commits with a timestamped message, and pushes. Does nothing when there are no changes.

### `notizen sync`

Rsyncs `source/` to a remote server.

| Flag | Description |
|------|-------------|
| `-s`, `--src` | Local source directory (default: `<root>/source`) |
| `-d`, `--dest` | Remote destination path (falls back to config) |
| `-n`, `--dry-run` | Preview without making changes |
| `--no-delete` | Keep remote files not present in source |
| `--no-recursive` | Non-recursive sync |

### `notizen specs <repo-path>`

Symlinks a repository's `specs/` directory into `source/Agents/Specs/<repo-name>/` and generates toctree `index.md` files inside the linked `specs/` directory.

Generated index files start with a `.. Generated by notizen. DO NOT EDIT.` marker line. Files without the marker are never overwritten unless `--force` is given; index files generated before the marker was introduced need a one-time `--force` run to adopt them. `--force` disables the check for every index file the run writes, so review the paths listed in the error message first.

| Flag | Description |
|------|-------------|
| `-n`, `--name` | Override the auto-detected repo name |
| `--force` | Overwrite index files not generated by notizen |

### `notizen superpowers <repo-path>`

Symlinks a repository's `docs/superpowers/` directory (design specs and implementation plans written by the Claude Code superpowers plugin) into `source/Agents/Superpowers/<repo-name>/` and generates toctree `index.md` files for the `specs` and `plans` sections. The same marker rules as `notizen specs` apply. Unlike `notizen plans`, which archives `~/.claude/plans`, this links documents that live inside the repository.

| Flag | Description |
|------|-------------|
| `-n`, `--name` | Override the auto-detected repo name |
| `--force` | Overwrite index files not generated by notizen |

Both linking commands assume no other process modifies the involved trees while they run. They are not transactional: validation failures stop before anything changes, but a later I/O failure can leave the link updated with only some index files written (each individual file write is atomic), and the `root/source` bootstrap happens regardless. Hand-written index files are only protected without `--force`.

## Configuration

Reads `~/.config/notizen/config.toml`, or `$XDG_CONFIG_HOME/notizen/config.toml` if set.

```toml
root = "/data/my-notes"

[remote]
host = "example.com"
user = "deploy"
port = 22
key  = "/home/you/.ssh/id_ed25519"
path = "/var/www/notes"
```

The `root` key sets the notizen data directory (default: `~/.notizen`). Root directory precedence: `--root` flag > `NOTIZEN_ROOT` env var > config.toml `root` key > `~/.notizen`.

Environment variables take precedence over the config file:

| Variable | Field |
|----------|-------|
| `NOTIZEN_ROOT` | Root data directory |
| `NOTIZEN_REMOTE_HOST` | `host` |
| `NOTIZEN_REMOTE_USER` | `user` |
| `NOTIZEN_REMOTE_PORT` | `port` |
| `NOTIZEN_REMOTE_KEY` | `key` |
| `NOTIZEN_REMOTE_PATH` | `path` |

## Template Customization

Put override templates under `~/.config/notizen/templates/`. They take precedence over the built-in defaults.

Built-in templates:

- `diary/entry.md.tmpl` -- diary entry body
- `diary/index.md.tmpl` -- year and month index
- `speckit/branch.md.tmpl` -- spec branch page
- `speckit/index.md.tmpl` -- spec index page
- `superpowers/index.md.tmpl` -- superpowers root index page
- `superpowers/section.md.tmpl` -- superpowers section page (specs, plans)

## Directory Structure

The root directory defaults to `~/.notizen` but is configurable via `--root`, `NOTIZEN_ROOT`, or config.toml.

```
<root>/
  source/
    Diaries/
      YYYY/
        index.md
        MM/
          index.md
          DD.md
    Agents/
      Specs/
        <repo-name>/  -> /path/to/repo/specs/
      Superpowers/
        <repo-name>/  -> /path/to/repo/docs/superpowers/

~/.config/notizen/
  config.toml
  templates/
    diary/
    speckit/
    superpowers/
```
